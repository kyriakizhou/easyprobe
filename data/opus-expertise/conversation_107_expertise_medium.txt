HUMAN: How do I handle database transactions properly in my Node.js application?

A: Transactions group multiple operations into an atomic unit - all succeed or all fail. In Node.js, use your ORM's transaction support (Prisma, TypeORM) or raw client transactions. Key: wrap related operations, handle errors properly, and be aware of connection pooling implications.

H: When should I use a transaction?

A: When multiple operations must succeed or fail together. Classic examples: transferring money between accounts (debit and credit), creating an order with line items, or any "all or nothing" operation. If partial completion would leave data inconsistent, use a transaction.

H: How do I implement it with Prisma?

A: Prisma has $transaction method. Either pass an array of operations: prisma.$transaction([op1, op2]). Or use interactive transactions: prisma.$transaction(async (tx) => { await tx.user.create(...); await tx.order.create(...); }). The interactive approach gives you more control.

H: What happens if an error occurs mid-transaction?

A: The transaction rolls back - all changes are undone as if nothing happened. That's the point! Your catch block handles the error, database stays consistent. With interactive transactions, throwing any error triggers rollback. Make sure to properly propagate errors.

H: What about long-running transactions?

A: Keep transactions short! Long transactions hold locks, blocking other operations. If you need to do slow work (API calls, file processing), do it outside the transaction. Only wrap the database writes. Set statement timeouts as a safety net.

H: Can transactions span multiple database calls in different functions?

A: Yes, but you need to pass the transaction client around. With Prisma interactive transactions, pass the tx object to functions that need it. This is cleaner than trying to manage transaction state globally. Design your functions to accept an optional transaction parameter.
