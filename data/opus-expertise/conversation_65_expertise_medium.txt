HUMAN: I'm seeing memory issues with large file processing. Users upload big files and the server runs out of memory.

A: Loading entire files into memory doesn't scale. The solution is streaming - process files chunk by chunk. Node.js streams, Python generators, or language-equivalent approaches. What's your use case - parsing CSV, processing images, or something else?

H: Mostly CSV files that can be gigabytes. We parse them, validate rows, and store in the database.

A: Perfect streaming use case. Read CSV as a stream, parse row by row, batch database inserts. At any moment, only a few rows are in memory. Node's readable streams with csv-parser, or Python's csv module with file iteration, handle this pattern.

H: How do I handle errors in the middle of a stream?

A: Track progress as you go - store how many rows processed. If error occurs, you can resume from that point. Consider wrapping the whole operation in a transaction or use idempotent imports (upsert based on unique key). Log the row number with errors for debugging.

H: What about validation? We need to reject files with too many bad rows.

A: Stream through once for validation (count errors), then again to import - or validate as you import with an error threshold. Keep running count of errors; abort if threshold exceeded. Consider: is partial import acceptable, or must the whole file succeed?

H: How do I show progress to the user? The upload could take minutes.

A: Background job pattern. Upload goes to storage (S3), API creates a job and returns job ID. Job worker processes the file, updating progress in database. Frontend polls the job status or uses WebSocket for real-time updates. Show percent complete based on bytes or rows processed.

H: What about timeouts? HTTP requests can't stay open that long.

A: Exactly why background jobs. Return immediately with job ID, process async. HTTP upload can timeout, but file is already in storage. Set generous but finite timeouts on the upload. For very large files, consider multipart upload directly to S3.
