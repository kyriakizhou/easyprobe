HUMAN: I'm seeing some memory leaks in my Node.js application. CPU and memory keep climbing until the server crashes. Any debugging tips?

A: Memory leaks in Node are frustrating but diagnosable. Start by taking heap snapshots with the built-in inspector. Run your app with --inspect flag, open chrome://inspect, and take multiple heap snapshots over time. Compare them to see what objects are growing.

H: I tried that but there are so many objects. Hard to find the culprit.

A: Focus on the delta between snapshots - sort by "Objects allocated between snapshots." Look for objects that shouldn't be accumulating. Common culprits: event listeners not being removed, closures holding references, growing arrays or maps used as caches without limits, and uncleared intervals.

H: We do have some event emitters. How do I check if that's the issue?

A: Use process._getActiveHandles() and process._getActiveRequests() to see what's keeping Node alive. For EventEmitters, check the listener count - if it keeps growing, you're adding listeners without removing them. Set emitter.setMaxListeners() to a small number to get warnings.

H: I found it - we're adding a listener on every API request but never removing it.

A: Classic issue! When you add listeners in request handlers, they must be cleaned up when the request ends. Either add them to the request/response object's 'close' or 'finish' event for cleanup, or restructure to add the listener once at startup if it's truly global.

H: What tools exist for ongoing monitoring to catch these earlier?

A: In production, use the --max-old-space-size flag to limit heap and crash earlier. For monitoring, tools like clinic.js, Prometheus with Node.js client, or APM solutions like DataDog track memory over time. Set up alerts when memory exceeds normal bounds.

H: Should I be worried about garbage collection pauses too?

A: At scale, yes. V8's GC can cause noticeable pauses. Keep individual objects small, avoid creating lots of short-lived objects in hot paths, and consider --trace-gc to see GC activity. Object pooling and streaming large data helps. But optimize after measuring, not before.
