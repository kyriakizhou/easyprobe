HUMAN: How do I implement proper request logging for my API?

A: Log requests for debugging, analytics, and audit. Include: timestamp, request ID, method, path, status code, duration, user ID. Use structured logging (JSON). Don't log sensitive data. Consider separate access logs from application logs.

H: What should I NOT log?

A: Passwords, tokens, API keys, credit card numbers, PII beyond what's needed. Sanitize request bodies and headers before logging. Redact Authorization header values. Be aware of GDPR and similar regulations regarding logged personal data.

H: How do I add request logging in Express?

A: Middleware that runs on every request. morgan for simple access logs. Custom middleware for rich structured logs: capture start time, attach request ID, log on response finish with duration calculation. Log at INFO level for normal requests.

H: How do I correlate logs across a request?

A: Generate unique request ID at entry. Attach to request object or use async local storage. Include in all log entries during that request. Return in response header (X-Request-Id) so clients can reference for support. Pass to downstream services.

H: Should I log request bodies?

A: Carefully. Useful for debugging but risky for privacy and storage. Consider: log only on errors, log truncated bodies, exclude sensitive endpoints (login, payment). Never log file upload bodies. Balance debugging value against risk.

H: How do I manage log volume and costs?

A: Log at appropriate levels - not everything needs to be logged. Sample high-volume endpoints (log 10% of health checks). Set log retention policies. Archive old logs to cold storage. Monitor log ingestion costs. Debug logging in production only temporarily.
