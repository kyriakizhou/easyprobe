HUMAN: How do I implement feature toggles for A/B testing?

A: Feature toggles for A/B testing need: consistent user assignment (same user always gets same variant), tracking which variant users saw, and analysis of outcomes. Use feature flag services (LaunchDarkly, Split, Optimizely) or build with clear assignment and tracking.

H: How do I ensure consistent variant assignment?

A: Hash user ID or session ID with experiment name, use result to assign variant. hash(user_id + "experiment_name") % 100 gives 0-99. 0-49 is variant A, 50-99 is variant B. This is deterministic - same user always gets same result. Libraries handle this.

H: How do I track which variant users see?

A: Log assignment events: {user_id, experiment_name, variant, timestamp}. Include experiment variant in analytics events for that feature. When analyzing, segment by variant. Store assignments in database or analytics platform.

H: How long should I run an A/B test?

A: Until statistically significant. Depends on traffic and effect size. Use sample size calculators - need thousands of users typically. Don't peek and stop early when seeing favorable results (common mistake). Decide sample size upfront, run until reached.

H: How do I analyze results?

A: Compare conversion rates between variants. Use statistical tests (chi-squared, t-test) to determine significance. Watch for: novelty effects, segment differences, and multiple comparison problems. A/B testing platforms do this analysis for you.

H: What about feature flag cleanup?

A: After experiment concludes, remove the losing variant code. Set a reminder or track flag creation dates. Dead feature flags accumulate as tech debt. Have a process: experiment ends → winner chosen → flag removed → code cleaned up.
