HUMAN: How should I approach performance testing before a big launch?

A: Performance testing phases: establish baseline, identify bottlenecks, optimize, retest. Types: load testing (normal load), stress testing (find limits), soak testing (long duration), and spike testing (sudden bursts). Start early - don't wait until launch week.

H: What tools should I use for load testing?

A: Popular tools: k6 (JavaScript-based, modern), Locust (Python, easy to write), JMeter (established, GUI-based), Gatling (Scala). Cloud options: AWS Load Testing, BlazeMeter. Choose based on team familiarity. k6 is great for developer-friendly scripting.

H: How do I create realistic test scenarios?

A: Analyze production traffic patterns: ratio of reads to writes, popular endpoints, session length, request sequences. Create test scenarios mimicking real user journeys - not just hammering one endpoint. Mix authenticated and anonymous traffic.

H: What metrics should I track during tests?

A: Response times (p50, p95, p99 - not just average), throughput (requests/second), error rate, and server resources (CPU, memory, connections, disk I/O). Set thresholds: p99 < 500ms, error rate < 0.1%. Fail test if thresholds exceeded.

H: How do I identify bottlenecks?

A: Profile while under load. APM tools show slow endpoints, database query times, external service latency. Check: database connections (pool exhaustion?), memory (GC pressure?), CPU (single-threaded bottleneck?). Often it's database queries - check slow query logs.

H: What's a reasonable load to test for?

A: Test at least 2x expected peak load. If you expect 1000 concurrent users, test with 2000. Find the breaking point - at what load does error rate spike or latency become unacceptable? This tells you capacity ceiling and when you need to scale.
