HUMAN: We're implementing a multi-leader replication setup for our PostgreSQL database across three data centers. What conflict resolution strategies should we consider?

A: Multi-leader replication has inherent conflict potential when same data is modified concurrently. Strategies: last-write-wins (LWW) using timestamps, merge (combine changes), custom conflict handlers per table, or conflict-free replicated data types (CRDTs). Choice depends on data semantics.

H: Our main concern is user profile updates. Two regions might update the same user simultaneously.

A: For user profiles, field-level LWW often works: each field updated at different time, latest wins. Store updated_at per field in JSONB, or use a changelog table. More sophisticated: operational transformation where both updates are applied if non-conflicting.

H: How do we detect conflicts in the first place?

A: Bidirectional replication systems track origin. BDR (Bi-Directional Replication for PostgreSQL) detects when same row is modified at different origins before receiving the other's change. Log conflicts for review. Automatic resolution for simple cases, flag for manual resolution otherwise.

H: What about auto-increment primary keys? They'll conflict across regions.

A: Never use auto-increment in multi-leader. Options: UUIDs (always unique), sequence ranges (region A gets 1-1M, B gets 1M-2M), or composite keys (region_id, local_id). UUIDs are simplest, slight storage overhead. For high insert volume, consider ULIDs for sortability.

H: We need strong consistency for inventory updates - can't oversell.

A: Multi-leader with strong consistency is essentially single-leader in disguise. Options: designate one region as authority for inventory writes, use distributed transactions (slow), or change the model. Consider: inventory reservations at each region, central reconciliation, with eventual consistency and oversell handling.

H: What replication technology would you recommend?

A: Logical replication with BDR or Citus for PostgreSQL. pglogical is another option. AWS has multi-region via Aurora Global Database (single writer) or custom setup. Evaluate: conflict handling capabilities, latency requirements, operational complexity, and vendor support.
