HUMAN: We're implementing a persistent data structure library. What are the key implementation techniques?

A: Persistent data structures: immutable, operations return new version, old versions still accessible. Techniques: path copying (copy only modified path to root), structural sharing (unchanged parts shared between versions), and fat nodes (store all versions at each node). Path copying most common.

H: How does structural sharing work for trees?

A: Modify leaf: create new nodes along path from leaf to root, link unchanged siblings. Example: tree with 7 nodes, modify one leaf = 3 new nodes (leaf + 2 ancestors), 4 shared. Logarithmic copying for balanced trees. Works well for tries, red-black trees, B+ trees.

H: What about persistent hash maps?

A: Hash Array Mapped Trie (HAMT): 32-way branching trie indexed by hash bits. 5 bits per level = 7 levels for 32-bit hash. Sparse nodes with bitmap indicating present children. Update: path copy through trie levels. Clojure's persistent data structures use this.

H: How do we handle garbage collection of old versions?

A: Reference counting: count references to each node, free when zero. Challenge: cycles (not in trees though). Or: defer to language GC. Epoch-based: versions associated with epochs, free entire epoch when no references. Trade-off: eager (free immediately) vs batched (free together).

H: What are the performance trade-offs compared to mutable structures?

A: Persistent: O(log n) overhead for updates (path copy vs O(1) mutation). But: no defensive copying, safe concurrent access, easy undo/history. Cache behavior: traversal follows pointers (less cache-friendly than arrays). Often acceptable trade-off for correctness and simplicity benefits.
