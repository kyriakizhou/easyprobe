HUMAN: How do I implement proper request validation middleware in Express?

A: Validation middleware checks requests before route handlers. Use libraries like zod, joi, or express-validator. Validate body, params, query separately. Return consistent error format. Reject early with 400 status.

H: How do I set up validation with zod in Express?

A: Create schemas, create middleware function: const validate = (schema) => (req, res, next) => { const result = schema.safeParse(req.body); if (!result.success) return res.status(400).json({ errors: result.error.issues }); req.body = result.data; next(); }. Use on routes.

H: How do I validate different parts of the request?

A: Separate schemas for body, params, query. Combine in middleware: validate({ body: bodySchema, params: paramsSchema, query: querySchema }). Merge validated data back to req. Each part has different validation needs.

H: What error format should I return?

A: Consistent format: { errors: [{ field: "email", message: "Invalid format", code: "INVALID_EMAIL" }] }. Include field path for nested objects. Return all errors at once, not just first. Machine-readable codes for programmatic handling.

H: How do I reuse validation schemas?

A: Define base schemas, compose for specific endpoints. User base schema reused in create, update, admin endpoints. Partial schemas for PATCH (all fields optional). Shared schemas reduce duplication and inconsistency.

H: What about custom validation rules?

A: Zod supports .refine() for custom validation. Add business rules: check uniqueness, validate relationships. Keep structural validation separate from business validation. Business rules might need async checks (database lookups).
