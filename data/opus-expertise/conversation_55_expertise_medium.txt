HUMAN: I'm trying to understand CORS. My frontend on localhost:3000 can't call my API on localhost:4000.

A: CORS (Cross-Origin Resource Sharing) is a browser security feature. Different origins (different port = different origin) require explicit server permission. Your API needs to send headers like Access-Control-Allow-Origin: http://localhost:3000 to permit the frontend to access responses.

H: How do I configure that in my Express server?

A: Use the cors middleware: const cors = require('cors'); app.use(cors({ origin: 'http://localhost:3000' })). For development, you might use cors() with no options to allow all origins, but restrict in production. This handles the headers automatically.

H: I'm still getting errors for POST requests even though GET works.

A: POST with certain content types (JSON) triggers a "preflight" request - the browser sends an OPTIONS request first asking if the actual request is allowed. Your server needs to handle OPTIONS and return appropriate headers: Access-Control-Allow-Methods, Access-Control-Allow-Headers.

H: What headers does my server need to allow?

A: Common ones: Content-Type, Authorization. In cors middleware: cors({ origin: 'http://localhost:3000', allowedHeaders: ['Content-Type', 'Authorization'] }). The cors package handles this, but if you're setting headers manually, don't forget OPTIONS handling.

H: What about cookies and authentication in CORS requests?

A: Credentials (cookies, auth headers) require extra config. Server: Access-Control-Allow-Credentials: true. Client: fetch with credentials: 'include'. When using credentials, you can't use wildcard (*) for Allow-Origin - must be specific origin. This trips people up often.

H: In production, should I allow all origins or just my frontend domain?

A: Just your frontend domain(s). Allowing all origins in production is a security risk - any site could make authenticated requests if the user is logged in. Explicitly list allowed origins. If you have multiple frontends, use a dynamic origin check.
