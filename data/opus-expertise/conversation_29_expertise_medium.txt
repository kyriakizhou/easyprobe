HUMAN: I'm trying to understand how to properly handle errors in my Node.js application. Any best practices?

A: Error handling in Node has several layers. Synchronous code uses try/catch. Async code uses promise .catch() or try/catch with async/await. Express needs explicit error middleware. Unhandled rejections and exceptions need global handlers. What patterns are you currently using?

H: Mostly try/catch in async functions. Sometimes errors just disappear.

A: Disappearing errors usually mean an unhandled promise rejection or missing await. Enable Node's --unhandled-rejections=strict flag to crash on unhandled rejections - this surfaces hidden issues. Always ensure promises are awaited or have .catch() handlers.

H: How should I structure error handling in an Express API?

A: Use a centralized error handling middleware as the last middleware. Controllers throw errors or call next(error). Create custom error classes with status codes and messages. The error middleware formats the response consistently. This avoids duplicated try/catch blocks everywhere.

H: What about distinguishing between errors I expect and bugs?

A: Great distinction. "Operational errors" are expected - validation failures, database down, rate limits. Handle gracefully with appropriate status codes. "Programmer errors" are bugs - null reference, assertion failures. These should crash in development and be fixed, not handled.

H: Should I log all errors?

A: Log operational errors at WARN or ERROR level with context. Include request ID, user ID, and relevant data for debugging. For programmer errors, log the full stack trace. Don't log expected "errors" like 404s at error level - they're normal flow, maybe DEBUG or INFO.

H: What about error messages sent to clients?

A: Never expose internal error details to clients in production - it's a security risk and confuses users. Send generic messages ("Something went wrong") with error codes for support reference. Include details in logs, not responses. In development, you can return full stack traces.
