HUMAN: How should I structure my React components? I'm seeing different patterns like containers, presentational, and hooks.

A: Component architecture has evolved. The "containers vs presentational" pattern (smart/dumb components) was popular with Redux. Hooks shifted thinking - logic extraction is now done with custom hooks. Modern approach: colocation (keep related code together), composition, and custom hooks for reusable logic.

H: Can you explain what colocation means practically?

A: Put related things together. Component file includes its styles, tests, and helper functions nearby (same folder or file). Feature folders contain all code for that feature rather than separating by type (all components in one folder, all tests in another). Reduces jumping around the codebase.

H: What about separating logic from UI? I have components doing both data fetching and rendering.

A: Extract data fetching to custom hooks. Component calls useUserData() and receives data + loading + error states. Component focuses on rendering. The hook is reusable and testable independently. This is the modern equivalent of the container pattern without the wrapper components.

H: How do I decide when to create a new component?

A: Extract when: logic is reused elsewhere, component becomes too long to understand (subjective, maybe 200 lines), you want to test something in isolation, or you want to use React.memo for performance. Don't over-extract - having 50 tiny components is also hard to follow.

H: What about component props? Sometimes they become a huge list.

A: Too many props often indicates a component doing too much. Group related props into objects: instead of userName, userEmail, userId, pass user={{name, email, id}}. Consider composition: pass children or render props instead of configuring everything via props.

H: How do I manage shared state between components?

A: Lift state to common ancestor for nearby components. Context for truly global state (theme, auth) but don't overuse - it's not a replacement for proper state management. For complex state, consider Zustand, Jotai, or Redux Toolkit. URL state for shareable/bookmarkable state.
