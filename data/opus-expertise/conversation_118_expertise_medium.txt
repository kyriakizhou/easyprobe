HUMAN: How do I implement proper request timeouts in my application?

A: Timeouts at multiple levels: HTTP client timeouts, database query timeouts, overall request timeouts. Set reasonable defaults, make them configurable. Timeout failures should be graceful with proper error messages.

H: What timeout values should I use?

A: Depends on operations. API calls to external services: 5-30 seconds. Database queries: 30 seconds max (investigate if longer). Overall request: 60 seconds. Internal service calls: 5-10 seconds. Start conservative, adjust based on actual performance.

H: How do I set timeouts in Node.js for HTTP requests?

A: With fetch: AbortController with setTimeout. With axios: { timeout: 5000 } config. Set both connection timeout (establishing connection) and read timeout (waiting for response) separately when possible. Handle timeout errors specifically.

H: What about database query timeouts?

A: PostgreSQL: SET statement_timeout = '30s' per connection or in pool config. This kills queries exceeding the limit. Also set in connection string. Application-level timeout as backup. Long queries shouldn't impact other users.

H: How do I implement an overall request timeout?

A: Middleware that starts timer when request arrives, aborts if not completed. Express: set req.setTimeout(60000). Important: clean up resources when timeout hits. Database connections, file handles should be released.

H: How should I handle timeout errors?

A: Return 504 Gateway Timeout or 408 Request Timeout. Log the timeout with context (which operation timed out, how long it took). Alert if timeout rate increases. Investigate root cause - timeouts often indicate performance problems.
