HUMAN: How do I implement proper error boundaries and fallbacks in React?

A: Error boundaries catch JavaScript errors in component trees and display fallback UI instead of crashing the whole app. Implement using componentDidCatch lifecycle or libraries like react-error-boundary. Place strategically around independent features.

H: Where should I place error boundaries?

A: Around independently functional parts of your app. Each major feature or route can have its own boundary. If comments crash, the rest of the page still works. Also wrap the entire app with a top-level boundary as a last resort.

H: How do I create an error boundary?

A: Class component with componentDidCatch and static getDerivedStateFromError. Or use react-error-boundary library: <ErrorBoundary fallback={<Error />}><MyComponent /></ErrorBoundary>. The library adds reset functionality and error reporting hooks.

H: What should my fallback UI show?

A: Depends on severity. Minor feature: "Something went wrong with comments. Try refreshing." Major feature: retry button and error report option. Full app crash: friendly error page with contact info. Don't show stack traces to users.

H: How do I report errors caught by boundaries?

A: In componentDidCatch or onError prop, send to your error tracking service (Sentry, Bugsnag). Include component stack, user context, and any relevant state. This is crucial for finding and fixing production errors.

H: Error boundaries don't catch async errors. How do I handle those?

A: Async errors need separate handling. Use try/catch with async/await. For data fetching, libraries like React Query have error handling built in. State machines (XState) can model error states explicitly. Handle loading, success, and error states systematically.
