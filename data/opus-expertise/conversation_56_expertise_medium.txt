HUMAN: What's the best way to handle form validation in a React application?

A: Form validation has client-side (instant feedback, UX) and server-side (security, source of truth) components. You need both. For React, popular libraries: react-hook-form for performance, Formik for feature-richness, or native controlled components for simple forms. What's your form complexity?

H: We have complex forms with conditional fields and multi-step wizards.

A: React Hook Form handles complex cases well - it uses uncontrolled components for performance, handles conditional fields, and has good TypeScript support. Combine with yup or zod for schema validation. For wizards, track step state and validate per-step before proceeding.

H: Should I validate as the user types or on submit?

A: Hybrid approach works best. Validate on blur (when user leaves field) for per-field feedback without being annoying during typing. Validate on submit for overall form. Don't show errors before user has interacted with the field - empty required fields shouldn't show errors on page load.

H: How do I sync validation between frontend and backend?

A: DRY approach: define validation schema in one place, share between frontend and backend. Zod schemas can be shared in TypeScript monorepo. Or generate frontend validation from OpenAPI spec. At minimum, ensure rules match even if implemented separately.

H: What about async validation, like checking if a username is taken?

A: Debounce to avoid excessive API calls - wait until user stops typing. Show loading indicator during check. Cache results for values already checked. Handle race conditions - only show result for the latest value if user keeps typing.

H: How do I display validation errors clearly?

A: Show errors near the relevant field. Use color and icons for quick scanning. Summary at top for long forms. Announce errors to screen readers (aria-live). Don't just show "invalid" - say what's wrong and how to fix it. "Email must be in format name@example.com" not just "Invalid email."
