HUMAN: We need to implement backward-compatible API evolution while supporting both Protocol Buffers and JSON clients. What are the versioning and compatibility constraints?

A: Proto3 has specific wire-compatibility rules. Safe changes: add optional fields, add new enum values, rename fields (wire uses numbers). Unsafe: change field types, change field numbers, remove required fields. JSON has different concerns: field name changes break JSON but not proto wire format.

H: We have both proto clients (internal) and JSON clients (external API). How do we reconcile?

A: Proto field names become JSON field names by default. If you use json_name option, you can have different JSON names. This lets you evolve proto field names while keeping JSON stable. But now you have two naming schemes to track.

H: What about removing a field that's no longer needed?

A: Never reuse the field number. Mark as reserved: reserved 5; reserved "old_field_name";. This prevents accidental reuse. Old clients sending the old field - new server ignores unknown fields (safe). New server not sending old field - old clients should handle missing fields (ideally with defaults).

H: How do we handle enum evolution?

A: Add new values freely. But old clients receiving new values see them as unknown (proto3 preserves unknown values, but code can't switch on them). Consider: enum value 0 should be UNKNOWN/UNSPECIFIED. Clients must handle unknown enum values gracefully.

H: What about major API changes that break compatibility?

A: New major version: package v2, separate proto files, separate endpoints. Run both versions simultaneously during migration. Clearly document breaking changes. Provide migration guide. Set deprecation timeline for old version. Consider: do you really need to break compatibility?

H: How do we test backward compatibility?

A: Wire compatibility tests: serialize with old version, deserialize with new version, and vice versa. Maintain corpus of historical payloads. CI checks that new proto definitions remain compatible. Tooling like buf has breaking change detection built in.
