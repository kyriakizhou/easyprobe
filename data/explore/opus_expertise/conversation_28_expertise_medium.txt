HUMAN: I need to implement file uploads in my web app. Users will upload images and documents up to 50MB.

A: Several decisions to make. Where to store files: cloud storage (S3, GCS) is typically best for production - scalable, durable, handles serving. For processing: do you need to resize images or scan documents? How many concurrent uploads and what's your bandwidth? 50MB is moderate but requires handling.

H: We're on AWS. I was thinking of just storing files in the application server filesystem.

A: Strongly recommend against that for several reasons. Server disk is ephemeral in most cloud setups, scaling to multiple servers means files aren't shared, no built-in CDN for fast delivery, and no redundancy. S3 is cheap and handles all these concerns. Use it.

H: How should the upload flow work? Upload to my server then to S3?

A: For files up to 50MB, direct upload to S3 using presigned URLs is better. Client requests a presigned URL from your API, then uploads directly to S3. This saves your server bandwidth and keeps upload logic simple. Your server just tracks metadata.

H: What about validating file types? I don't want executables or malicious files.

A: Multi-layer approach. Client-side: check file extension and MIME type (can be bypassed, but filters obvious mistakes). Server-side: use libraries that detect actual file type by magic bytes, not just extension. For images, try to load/process them - invalid images will fail. For documents, consider virus scanning.

H: How do I handle large files that take a long time to upload?

A: S3 multipart upload for files over 5MB - splits into chunks, handles network interruptions. On the client, show progress bar using XHR upload progress events or fetch with streams. Set appropriate timeouts. Consider resumable upload protocols for very large files.

H: What about serving files back to users? Do they download from S3 directly?

A: Usually through presigned URLs for private files or CloudFront (CDN) for public files. Presigned URLs have expiration for security. For images, consider processing on-the-fly: tools like imgproxy or CloudFront Lambda@Edge can resize images per request, so you only store originals.
