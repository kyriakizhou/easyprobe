HUMAN: I want to add analytics to track user behavior in our app. What's the right approach?

A: Analytics architecture depends on your needs: basic page views and events, or complex funnel and cohort analysis? Common stack: client-side tracking (event emission), event collection service, and analytics tool (Mixpanel, Amplitude, self-hosted like Plausible, or data warehouse with BI tools).

H: We want to understand user journeys and where people drop off in our signup flow.

A: Funnel analysis requires: tracking each step as an event with user/session identifiers, ensuring events are ordered correctly (timestamp), and tools that can build funnels from event streams. Mixpanel, Amplitude, and PostHog handle this well. Define your events carefully upfront.

H: What events should we track?

A: Start with key user actions: sign_up_started, sign_up_step_1_completed, sign_up_completed, key_feature_used, subscription_started, etc. Include relevant properties: source, plan type, A/B test variant. Track enough to answer business questions but don't track everything - it creates noise.

H: How do we track users across sessions and devices?

A: Before login, use anonymous IDs (stored in cookie/localStorage). After login, alias anonymous ID to user ID. Good analytics tools handle this "identify" flow. Cross-device tracking is hard without login - some use fingerprinting but it's privacy-invasive. Focus on logged-in user journeys.

H: What about privacy and GDPR?

A: Get consent before tracking non-essential analytics. Anonymize data where possible. Don't track PII in events unless necessary. Allow users to delete their analytics data. Some companies self-host analytics (Plausible, PostHog) for more control. Document what you track.

H: Should analytics code be separate from product code?

A: Use an analytics abstraction layer. Call analytics.track('event', properties) rather than mixpanel.track() directly. This lets you swap providers, add multiple destinations, and test without hitting real analytics. Keep tracking calls near the user action for clarity.
