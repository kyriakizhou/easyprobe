HUMAN: We're experiencing intermittent 504 timeouts on some API endpoints. They work most of the time but randomly fail. How do I debug this?

A: Intermittent timeouts are tricky. Common causes: slow database queries under load, external API calls timing out, connection pool exhaustion, memory pressure causing GC pauses, or infrastructure issues. Start by adding detailed timing logs to the affected endpoints.

H: I added timing and see that sometimes database queries take 30+ seconds when they usually take 100ms.

A: Database query variance often indicates: missing indexes being needed as data grows, table locks from concurrent writes, resource contention during peak load, or query plan changes. Check your slow query log. Does the slowness correlate with specific query patterns or time of day?

H: It happens during peak traffic around lunchtime. The query is a search across a large table with multiple filters.

A: Under load, the database server might be CPU or I/O constrained. Check your database server metrics during peak times. Also examine if connection pooling is configured correctly - you might be exhausting connections, causing queries to wait. How many connections can your database handle?

H: We have a connection pool of 10 connections, database allows 100 max.

A: 10 connections serving peak traffic might be a bottleneck. Each pending request waits for a connection. Calculate: if queries take 100ms and you get 200 requests/second, you need 20 concurrent connections minimum. Increase pool size, but also consider query optimization and caching.

H: What about adding a read replica for search queries?

A: Good thinking! Read replicas offload read-heavy queries from your primary. Search is typically read-heavy and slightly stale data is acceptable. Route search queries to the replica. Also consider adding Redis caching for frequently accessed data to reduce database load further.

H: How do I set up alerts to catch this earlier?

A: Monitor p95 and p99 latency, not just averages - they reveal intermittent slowness. Alert when latency exceeds a threshold. Also monitor database connection pool utilization, active connections, and query times. Dashboards with time correlation help see patterns.
