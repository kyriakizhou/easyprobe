HUMAN: What are some common security vulnerabilities I should watch out for in a web application?

A: The OWASP Top 10 covers major threats. Most critical for web apps: injection (SQL, command), broken authentication, XSS (cross-site scripting), sensitive data exposure, security misconfiguration, and broken access control. Each requires different defenses. What stack are you using?

H: Node.js with Express and PostgreSQL.

A: Key defenses for that stack: parameterized queries for SQL (never string concatenation), helmet middleware for security headers, CSRF protection, proper password hashing (bcrypt), HTTPS everywhere, secure session configuration, and input validation. Let me highlight specific risks.

H: How do I prevent SQL injection?

A: Use parameterized queries exclusively. With pg driver: query('SELECT * FROM users WHERE id = $1', [userId]). Never: query('SELECT * FROM users WHERE id = ' + userId). ORMs like Prisma use parameterized queries by default. Never trust user input in query construction.

H: What about XSS attacks?

A: React/Vue escape output by default - that helps. Dangerous: using dangerouslySetInnerHTML or v-html with user content. On the server: set Content-Security-Policy headers (helmet helps), sanitize any user HTML you must allow (DOMPurify), and encode output in non-HTML contexts.

H: How do I secure authentication?

A: Bcrypt for password hashing with cost factor 10+. Rate limit login attempts. Use secure, httpOnly, SameSite cookies for sessions. Implement account lockout. Consider 2FA. Never log passwords. Use timing-safe comparison for password checks. Invalidate sessions on password change.

H: What security headers should I set?

A: helmet middleware sets many automatically. Critical ones: Content-Security-Policy (restricts script sources), X-Content-Type-Options: nosniff, X-Frame-Options: DENY (prevents clickjacking), Strict-Transport-Security (forces HTTPS). Review and customize for your needs.
