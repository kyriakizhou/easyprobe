HUMAN: How do I implement proper image optimization for my web application?

A: Image optimization involves: serving appropriate sizes (responsive images), modern formats (WebP, AVIF), compression, lazy loading, and CDN delivery. Can significantly impact page load times - images are often the heaviest resources.

H: What formats should I serve?

A: Serve WebP as primary - much smaller than JPEG/PNG with similar quality. AVIF is even better but less supported. Use <picture> element with fallbacks: AVIF → WebP → JPEG. Or use a CDN that does format negotiation based on browser Accept header.

H: How do I handle responsive images?

A: Use srcset attribute to provide multiple sizes. Browser picks appropriate size based on viewport. Define sizes attribute to help browser choose. Or use <picture> for art direction (different crops for different sizes). Don't serve a 2000px image to mobile.

H: Should I process images on upload or on-the-fly?

A: Both have merit. On-upload: generate all needed sizes immediately, simple to serve. On-the-fly: generate sizes on first request, cache for subsequent requests, more flexible. CDNs like Cloudinary, imgix do on-the-fly with edge caching.

H: What compression settings should I use?

A: JPEG: quality 80-85 is usually good balance. WebP: quality 75-80 achieves similar visual quality with smaller size. Test with your actual images - some tolerate more compression. Use tools like squoosh.app to compare.

H: How do I implement lazy loading?

A: Native: <img loading="lazy">. Works in modern browsers. For more control, use Intersection Observer API or libraries. Lazy load below-the-fold images. Consider placeholder: low-quality blur, skeleton, or solid color. Don't lazy load LCP (Largest Contentful Paint) image.
