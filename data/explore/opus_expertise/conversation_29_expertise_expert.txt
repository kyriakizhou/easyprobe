HUMAN: We're implementing a zero-downtime database migration between PostgreSQL versions with significant schema changes. What's the approach?

A: Major version upgrades with schema changes require careful planning. Options: pg_upgrade for in-place version upgrade (then separate schema migration), logical replication to new version (replicate while making changes), or blue-green with application dual-write.

H: We're going from PostgreSQL 12 to 15 with a significant schema refactoring - splitting tables, changing relationships.

A: Combined version upgrade and schema change is complex. Recommended approach: upgrade version first (pg_upgrade is fastest), then schema migration on the new version. Alternatively: set up PG15 with new schema, use logical replication plus transformation layer to sync from old schema.

H: How does the transformation layer work with logical replication?

A: Logical replication sends row changes. Intercept with trigger-based capture or use pglogical with hooks. Transform old schema rows to new schema format in a subscriber side transformer. This is complex but allows running both schemas simultaneously.

H: What about application changes needed for the new schema?

A: Dual-write pattern during migration. Application writes to both old and new schema. Read from old initially. Once new schema is caught up and validated, switch reads to new. Eventually stop writing to old. Feature flags control which schema is active.

H: How do we validate data consistency between old and new?

A: Consistency verification job. Compare old and new schemas row by row (or sample for large tables). Account for transformation logic. Run continuously during migration. Alert on divergence. Reconciliation process to fix discrepancies.

H: What's the rollback plan if something goes wrong?

A: Keep old system running throughout migration. Don't decommission until new is proven. With dual-write, switch reads back to old if issues. Data written only to new during new-primary period needs reverse sync if rolling back. Plan for this before you start.
