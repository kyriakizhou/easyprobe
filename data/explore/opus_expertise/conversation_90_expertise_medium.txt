HUMAN: How do I build a good search experience with filters and facets?

A: Good search combines full-text search with structured filtering. Core components: search query parsing, result ranking, faceted navigation (showing filter options with counts), and efficient filtering. The UX matters as much as the backend.

H: What's the difference between filters and facets?

A: Filters are the active selections (Category = "Electronics"). Facets are the available options with counts shown to users (Electronics (42), Clothing (28)...). Facets update based on current filters - if you filter by Electronics, facets show options within Electronics.

H: How do I implement faceted counts efficiently?

A: Elasticsearch aggregations are designed for this. After filtering, request aggregations on facet fields - it returns counts per value. For PostgreSQL, you might need multiple GROUP BY queries or window functions. Caching facet counts for common filter combinations helps.

H: Should I update facet counts as users add more filters?

A: Yes, this is good UX - users see what options remain. Apply current filters, re-aggregate for facets. Each filter narrows options. Show "(0)" or hide unavailable options. Balance UX (users see what's possible) versus simplicity (hide empty options).

H: How do I handle the search query itself?

A: Parse intelligently. Simple queries: full-text search across relevant fields. Consider: stemming, synonyms, typo tolerance. Advanced queries: support field-specific search (author:smith), quoted phrases, exclusions (-term). Many search engines handle this out of box.

H: What about sorting and relevance?

A: Default to relevance-sorted (best matches first). Offer explicit sort options: price, date, popularity. Relevance ranking considers: text match quality, field importance (title matches worth more than description), freshness, popularity metrics. Tune based on user behavior.
