HUMAN: I'm implementing search functionality for our e-commerce site. Should I use Elasticsearch or just database queries?

A: Depends on your scale and requirements. For simple search with small catalogs (few thousand products), PostgreSQL's full-text search or LIKE queries might suffice. For larger catalogs, faceted search, relevance tuning, or typo tolerance, Elasticsearch is worth the operational overhead.

H: We have about 50,000 products with attributes like category, brand, price, and user ratings.

A: That's in the gray zone. PostgreSQL full-text search with proper indexing could handle it, but you'd struggle with faceted search (showing filter counts) and relevance tuning. If users expect Amazon-like search experience, Elasticsearch will get you there faster.

H: What about Algolia or similar hosted solutions?

A: Algolia is excellent - instant search, typo tolerance, faceting, and near-zero ops. But it's expensive at scale with per-operation pricing. For 50,000 products with reasonable traffic, cost might be fine. Compare: Algolia saves developer time, self-hosted saves money long-term.

H: If we go with Elasticsearch, how do we keep it in sync with our database?

A: Several patterns. Simplest: reindex on product changes (direct write after database commit). More robust: use a change data capture tool (Debezium) or message queue to process updates asynchronously. Include a "last_indexed" timestamp and have a periodic full reindex job as a safety net.

H: How do we handle faceted search? Like showing (Color: Red (15), Blue (23))?

A: Elasticsearch aggregations handle this. You run a filtered query but also request aggregations on facet fields. The response includes counts for each facet value in the filtered results. With proper mapping (keyword fields for facets), it's fast even on large datasets.

H: What about search result relevance? Users complain products don't show in expected order.

A: Relevance tuning is part art. Start with Elasticsearch's defaults, then customize: boost matches in title over description, boost newer or higher-rated products, use function_score for business rules. A/B test changes. Consider user behavior signals like clicks and purchases for personalization.
