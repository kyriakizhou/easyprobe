HUMAN: We're implementing a byte-code interpreter. What are the key optimization techniques?

A: Interpreter optimizations: direct threading (computed goto instead of switch), inline caching (remember resolved method/property), superinstructions (combine common sequences), and register-based vs stack-based design. Also: bytecode design matters - fewer dispatches = faster.

H: How does inline caching work?

A: Cache lookup results at call sites. First call to obj.foo resolves foo in obj's class - cache the offset. Next call with same class type: use cached offset directly. Polymorphic inline cache: handle few different types. Megamorphic: fall back to general lookup. Huge win for dynamic languages.

H: What's the difference between threaded code approaches?

A: Switch threading: big switch on opcode, one dispatch per instruction. Direct threading: each instruction ends with jump to next instruction's code. Subroutine threading: call instruction handlers. Context threading: JIT inline handlers. Direct threading avoids branch prediction issues of switch.

H: When should we JIT compile instead of interpreting?

A: JIT when: code is executed many times (hot), dynamic optimization opportunities exist (inline caching misses suggest optimization), or specific operations are expensive in interpreter. Mixed mode: interpret first, JIT compile hot paths. Profile-guided: JIT based on actual execution profile.

H: How do we balance interpreter complexity with JIT compilation?

A: Simple interpreter: fast to develop, easier to debug, baseline for correctness. Complex interpreter optimizations: diminishing returns if good JIT exists. Strategy: interpreter for startup and cold code, invest in JIT for hot code. Tiered: fast JIT for quick startup, optimizing JIT for peak performance.
