HUMAN: I need to add internationalization to our React app. What's involved?

A: I18n involves: extracting strings into resource files, loading translations based on locale, handling pluralization and gender, formatting dates/numbers per locale, and possibly RTL layout support. Common tools: react-i18next, react-intl, or FormatJS.

H: How do I structure translation files?

A: Common approaches: one file per language (en.json, es.json), or namespaced by feature (auth/en.json, dashboard/en.json). JSON or ICU message format. Keep keys hierarchical and semantic: "auth.login.button" not "button1". Flat vs nested is team preference.

H: How do I handle dynamic content like "You have 1 message" vs "You have 5 messages"?

A: Pluralization rules differ by language. ICU message format handles this: "{count, plural, one {# message} other {# messages}}". Libraries like react-intl parse this. Don't just check count === 1 - some languages have multiple plural forms (Russian has several).

H: What about variables in strings like "Welcome, {name}"?

A: Use interpolation syntax. Most libraries support it: "Welcome, {{name}}" or "Welcome, {name}". Pass variables to the translation function: t('welcome', { name: user.name }). Never concatenate translated strings - word order differs by language.

H: How do we manage getting translations from translators?

A: Export translation files to translators, import their work. Tools like Lokalise, Phrase, or Crowdin provide translation management, version control, and collaborative workflows. They can integrate with your repo. Machine translation can provide first drafts, but professional review is recommended.

H: What about non-text content like images and icons?

A: Images with text need localized versions. Consider SVG with embedded text that can be localized. Icons are usually fine, but some have cultural meanings. Color associations vary by culture. Right-to-left languages flip layouts. Audio/video may need localized versions.
