HUMAN: I'm designing a notification system - push notifications, emails, and in-app notifications. How should I architect this?

A: Start by separating concerns. You need: event producers (parts of app that trigger notifications), a notification service that decides what to send and to whom, and delivery channels (push, email, in-app). Use a message queue between producers and the notification service for decoupling.

H: Should all notification types go through the same system?

A: Yes, unified is better. Event like "order shipped" triggers the notification service, which determines: send push notification, email, and in-app. Users can have preferences per channel. Single source of truth for "what happened" with multiple delivery mechanisms.

H: How do I handle user preferences? Some users want email but not push.

A: Store user notification preferences: global and per-category. For example: marketing emails off, order updates via push and email, comments only in-app. Your notification service checks preferences before sending. Provide a granular settings UI. Honor unsubscribe instantly.

H: What about notification fatigue? We don't want to spam users.

A: Implement rate limiting and consolidation. Don't send a push for every message in a conversation - consolidate: "5 new messages from John." Set maximum notifications per time period. Prioritize - some notifications can wait or be batched (daily digest). Let users control frequency.

H: How do I store in-app notifications?

A: Simple table: user_id, notification_type, content (JSON), read status, timestamp. Index by user_id and created_at for efficient "get unread" queries. Consider archiving or deleting old notifications. Real-time updates via WebSocket when new notifications arrive.

H: How do I handle push notification delivery failures?

A: Push is inherently unreliable - devices offline, tokens expire, users uninstall. Don't treat failure as critical. Remove invalid tokens when provider tells you. For critical notifications, consider fallback to SMS or email. Track delivery metrics to understand reach.
