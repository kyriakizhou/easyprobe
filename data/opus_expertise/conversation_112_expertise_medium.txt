HUMAN: How do I handle file downloads in my web application properly?

A: File downloads involve: setting correct headers, streaming large files, handling range requests for resumable downloads, and security considerations. Don't load entire files into memory - stream them. Set Content-Disposition header to trigger download.

H: What headers do I need to set?

A: Essential headers: Content-Type (file MIME type), Content-Disposition: attachment; filename="file.pdf" (triggers download, sets filename), Content-Length (file size for progress bars). For resumable downloads, also Accept-Ranges: bytes.

H: How do I stream a file without loading it all into memory?

A: In Node.js: fs.createReadStream(filePath).pipe(res). The file is read and sent in chunks. For S3, use getObject and pipe the Body stream. Never use fs.readFile for large files - it loads everything into memory first.

H: What about downloads from S3?

A: Two options: proxy through your server (stream from S3 to client), or presigned URLs (client downloads directly from S3). Presigned URLs are better - saves your bandwidth and scales better. Generate with short expiration for security.

H: How do I support resumable downloads?

A: Handle Range header. Client sends Range: bytes=1000-2000. Server responds with 206 Partial Content, Content-Range header, and only that byte range. Libraries exist to handle this. Important for large files where connections might drop.

H: Any security concerns with file downloads?

A: Validate file paths to prevent path traversal attacks. Don't let users specify arbitrary paths. Use allowlists of downloadable files or verify user has permission. Set X-Content-Type-Options: nosniff to prevent MIME sniffing. Consider download rate limiting.
